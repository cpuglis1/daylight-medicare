## Operate locally

Check the job:

```sh
launchctl print gui/501/com.daylight.advisor-first.8893
```

After an authorized source change, restart only this variant:

```sh
launchctl kickstart -k gui/501/com.daylight.advisor-first.8893
```

Stop without deleting any records:

```sh
launchctl bootout gui/501/com.daylight.advisor-first.8893
```

Start it again from this folder:

```sh
launchctl bootstrap gui/501 "$PWD/runtime/com.daylight.advisor-first.8893.plist"
```

The checked-in local plist uses `../../infrastructure/daylight-data/.venv/bin/python`, `--local-research` and explicit `--identity-research`; the dependency is `psycopg`, already installed locally. The service binds only to loopback. The exact private PostgreSQL cluster and selected source/build receipts must pass their existing ownership/read-only checks. `--local-research` constructs the original accepted-reference adapter; `--identity-research` separately enables trusted internal source-identity inspection, with all consumer purposes held. Omitting either flag disables its corresponding connection without changing source acceptance. The plist and local physical-target guard are not portable cloud configuration: hosting requires a separately bound target, roles, secrets, network/pooling and backup/restore checks. Do not restart other Daylight jobs, restore their databases or reset the shared ledger as part of this variant's rollback.

When changing launch arguments, `kickstart` does not reread the plist. Use the documented separate bootout/bootstrap steps, confirm the old process exited, and check the new job and API afterward. This work's initial immediate bootstrap returned macOS error 5; the original service was recovered, then the updated configuration started successfully in separate steps. Exact attempts and successful checks are retained in the evidence packet.
