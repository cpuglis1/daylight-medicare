# D86/D73 caregiver learning pilot

**Superseded by the owner's general-framework correction.** The caregiver-specific runtime was removed. This packet is retained as historical evidence; see the [shared implementation](../advisor-framework-20261104/README.md). The original script depends on the archived pilot code and is not the current evaluation entry point.

The pilot covers one outcome on the advisor-first backend: a caregiver can explain why reviewing an Original Medicare supplement involves what the policy helps pay when care is used, as well as its monthly price. This applies when the existing reports identify a caregiver, a current coverage review, and Original Medicare with a supplement. It uses the retained [Medigap teaching fact](../../alternatives/advisor-first/web/teaching-facts.json), based on [Medicare.gov](https://www.medicare.gov/health-drug-plans/medigap/ready-to-buy).

The [outcome and response policy](../../alternatives/advisor-first/learner_review.py) specify what counts as applying the concept, which misconceptions matter, one short lesson, and a different example for a repair. With unclear familiarity, Daylight asks about this concept before ZIP intake. A learner who already applies it can advance immediately. When the learner is new, Daylight explains the one idea and asks a practical question about applying it. A continued misunderstanding can get one alternate example; the advisor can still make practical progress with uncertainty open. The conversation honors a decline, an explicit stop, required clarification and unrelated requests.

The existing interpretation stage can propose a learner observation with an exact quote. The service checks the quote and learner scope and stores a bounded status and evidence fingerprint in existing owner- and visit-bound v3 RAM. These statuses are tentative interpretations. A matching quote confirms provenance; it does not independently establish that the model understood the quote. The new memory is separate from prior familiarity reports, lesson delivery, saved profile and beneficiary facts. The existing response and source checks still apply to the actual delivered lesson and question. A failed response does not mark its teaching or probe as delivered.

The current goal also guides practical progress. After the core review inputs, if the advisor has no targeted question and the person has not paused, it can offer help finding a recent premium notice. The follow-up is conversational and creates no new intake field. None of the education signals establishes policy identity, cost, doctor or medicine participation, eligibility, or personal suitability. This change preserves all 41 meanings, provider consent, the two typed stages and one finite-answer stage, existing visual presentation, the shared budget and existing evidence and recommendation holds.

## Evaluation method

- **Scripted service journeys:** the [tests](../../alternatives/advisor-first/tests/test_learner_review.py) pass controlled responses through the actual interpretation and composition validators. Check novice, experienced, misconception, decline, wrong-subject and unsupported quotes, clarification, and practical continuation.
- **Fictional live comparison:** [compare_live.py](compare_live.py) uses GPT‑6.1 Sol at low effort, the same opening and underlying fictional facts, one isolated guest store per arm, the existing consent and shared accounting, and no evaluation retries. It answers the question actually displayed and stops when there is no matching scripted answer, the response fails, or eight sends complete. The baseline omits the pilot, prompt-only adds its general behavioral instructions, and backend uses the implemented policy. These are small, stochastic observations. The histories diverge in response to what was asked; timings and cost are measured run outcomes rather than controlled per-turn estimates.
- **Observed users:** still needed. On a fictional task with a caregiver unfamiliar with the subject and another already familiar with it, have a reviewer score whether each can explain the cost distinction, identify a concrete next action, and distinguish preparation from verified results. Record errors, burden, and whether the conversation can continue, while letting participants skip a question. The [D73 evidence definitions](../../docs/product/STRATEGIC_THESIS.md#evidence-definitions-for-the-first-cohort) apply. Model output and scripted user replies do not prove human learning.

The first backend run asked the probe but bypassed its teaching and application step after interpretation also recognized a clarification request. The [first result](backend-first-attempt.json) is retained. The controller now allows a probe answer about this outcome to enter the reviewed teaching path while preserving other clarification requests. A regression test covers that handoff.

The experiments together accounted for $0.7020196, including $0.1020825 for the initial backend attempt. The prompt-only arm demonstrated that prompting can elicit useful teaching; the stronger backend evidence is the inspectable separation of reported knowledge, teaching and applied evidence, with bounded progression and continuation. These samples are too small to establish comparative reliability. The corrected run repeated baseline and document advice on some routine intake turns; the final prompt explicitly discourages that repetition. The wording refinement was not independently rerun with the provider. The scripted checks exercise the reply after the document offer.
